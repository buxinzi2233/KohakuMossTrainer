# 块算子的精度（fp16 / bf16）

每个块算子内核遵循的精度规则、各内核如何与 eager 参考实现比较，以及算子如何针对每个问题选择内核或 `torch.compile`。

这些规则适用于各后端中的 `rms_norm`、`rms_norm_mod`、`qk_norm_rope`、`situ_glu`、`gated_residual`、`token_mse`、融合 linear 算子（`linear_situ`、`linear_gated_residual`、`linear_qk_rope`）和优化器步内核：

| 后端 | 适用位置 |
| --- | --- |
| Triton | sm80+ 和 XPU |
| TileLang | sm70 / sm75 |
| `compile` | 每个通过编译探测的设备（GPU 上使用 Triton 探测，CPU 上使用主机 C++ 编译器）；对 eager 参考实现进行 `torch.compile` |
| eager | 每个设备（参考实现） |

<a id="eager-reference-and-error-statistics"></a>
## Eager 参考实现和误差统计

- eager 后端（`kohakumoss_kernels/backends/eager`）定义每个算子的计算内容。它以 `promote(input, fp32)` 计算，并仅舍入一次到输出 dtype，因此相同代码在 fp64 输入上运行就是 fp64 参考实现。
- 逐样本张量（`shift`、`scale`、`gate` [B, D]，以及 q/k 权重）在每个内核中都通过其步长读取：骨干网络传入一个 [B, 6, D] 张量的 `mod[:, k]` 切片（行步长 6 D），没有后端会复制它们。测试将它们构建为具有不同行的这类切片，并在叶张量中保留布局（`_blockops_harness._leaf`）；每个算子都有一个将跨步向量按行主序读取的错误变体，必须检测出来。
- 每个测试都配有一个必须被拒绝的错误变体（错误的片段、错误的轴顺序、交换两半、丢弃门控、丢弃权重、耦合权重衰减）。

<a id="error-statistics"></a>
### 误差统计

代码位于 `kohakumoss_kernels/error_stats.py`；测试检查位于 `tests/_util/error_stats.py` 和 `tests/kernels/blocks/_blockops_harness.py`。

- **测量内容。** 对每个输出和输入梯度，将相同 dtype 下的内核和 eager 组合都与 fp64 参考实现比较：余弦相似度，以及绝对误差和相对误差（在非零参考值上计算 |out - ref| / |ref|），每项都统计均值 / 中位数 / 最小值 / 最大值。
- **写入位置。** 每次检查都会将该表以及较差列表（内核比 eager 更差的每一项汇总统计）追加到 `$KOHAKUMOSS_PRECISION_DIR/<test>.jsonl`。
- **测试何时失败。** 仅在发生退化时：eager 为有限值而内核为非有限值，或者余弦差额达到 eager 的 `MAX_ERROR_RATIO`（10）倍及以上，或者同一汇总项（均值、中位数）的绝对和相对误差同时达到该倍数。最大值 / 最小值从不导致失败；较差列表中的条目需要书面说明原因或修复。
- **选择。** 在没有退化的内核中选择最快的一个。

<a id="arithmetic-rules-every-kernel-follows"></a>
## 每个内核遵循的运算规则

- 加载为 fp32，以 fp32 计算，在存储时舍入一次：算子的每个中间结果都保持 fp32。
- 算子返回 eager 参考实现所返回的结果；残差流折叠（`kohakumoss.model.numerics`）使激活保持在 fp16 范围内。

<a id="gemms-and-fused-epilogues"></a>
### GEMM 和融合尾处理

- GEMM 累加器为 fp32，融合尾处理直接读取累加器。当反向计算需要激活前的值时（`linear_situ` 保存 `[up | gate]`，`linear_qk_rope` 保存归一化前的 q / k，`linear_gated_residual` 在训练门控时保存投影），保存的副本是累加器舍入一次后的结果；对于 `linear_qk_rope`，归一化统计从该舍入后的副本计算，使前向和反向看到相同值。
- `linear_qk_rope` 将 `dq` 和 `dk` 写入一个 `[N, 2 D]` 缓冲区的两个列半区，并将 `dy = [dq | dk] @ [Wq; Wk]` 作为单次 GEMM：一次 fp32 累加和一次舍入，而组合实现会分别舍入 `dq Wq` 和 `dk Wk`，再对其和舍入一次。
- 融合 linear 算子以存储 dtype 接收权重（和偏置），包括 fp32 主权重（`backends/_master.py`）：
  - 矩阵乘法操作数在算子内部转换为激活 dtype；
  - 保存的张量是主权重本身；
  - 权重梯度是对 16 位操作数执行一次 GEMM，其 fp32 累加器直接以存储 dtype 存储（fp32 主权重直接得到 fp32 结果）；
  - autocast 下的 fp32 激活首先转换为 autocast dtype，与 autocast 转换 linear 输入的方式一致；`linear_gated_residual` 的残差流 `x` 保持其 dtype（在 TileLang 上，fp32 流与 16 位投影组合时使用 split 路径）。
- `linear_gated_residual` 融合路径以激活 dtype 保存用于门控梯度的投影，与 eager 组合一致。

<a id="row-statistics-and-rope"></a>
### 行统计和 RoPE

- 行统计（`rms_norm*`、`qk_norm_rope`）使用 IEEE 除法和平方根（`tl.div_rn`、`tl.sqrt_rn`；TileLang 构建时不启用 fast math）。`rstd` 以 fp32 保留供反向计算使用。
- RoPE 角度是对 fp32 相位 `pos * band` 计算得到的 fp32 `sin` / `cos`（CUDA 上使用全范围 libdevice），与 eager 参考实现的计算方式一致。

<a id="reductions"></a>
### 归约

- 跨行归约（`d_weight`、`d_shift`、`d_scale`、`d_gate`、q/k 归一化权重梯度）采用按固定顺序求和的逐图块部分结果：每个*片段图块*（一个样本中的若干行）一个程序，然后对每个样本求和。固定顺序使梯度在多次运行间按位可复现。
- 每个图块逐行块将 fp32 乘积累加到其部分结果，每个归约量一个槽位（`rms_norm_mod`：`[T, 2, D]`，槽位 0 是 `g x_hat` 之和，槽位 1 是 `g` 之和），逐样本求和再按图块顺序累加该样本各槽位的图块部分结果。尾处理以 fp32 形成 `d_weight = sum_b (1 + scale_b) S_gx`、`d_scale = w S_gx`、`d_shift = S_g`。
- `token_mse` 的总量按行块以 fp32 计算，各块部分结果按固定顺序求和。

<a id="optimizer-step-kernels"></a>
## 优化器步内核

- AdamW 存储 `m` 和 `r = sqrt(v)`：平方梯度永远不会进入 16 位存储（fp16 `v` 在低于 6e-8 时下溢；其平方根不会）。
- 参数写回：

  | 模式 | dtype | 行为 |
  | --- | --- | --- |
  | `nearest` | | 舍入到最近值 |
  | `stochastic` | 仅 bf16 | 基于计数器的 (index, seed) 32 位哈希提供被丢弃的 16 位，因此期望值等于 fp32 更新值 |
  | `kahan` | fp16, bf16 | 参数加上同 dtype 的补偿缓冲区；参数值为 `p + comp`，其与 fp32 主权重的差异在补偿量的一个 ULP 以内 |

- 8 位状态：每块 256 个值，将 `m` 存为 int8、`r` 存为 uint8 编码，编码对应 `sqrt(|x| / block_absmax)`，将编码范围更多地分配给小幅值。
- `seed` 必须每步推进，并且在数据并行的各 rank 之间相同。

<a id="kernel-or-compile-per-problem"></a>
## 按问题选择内核或编译路径

每个已注册的算子都是一个 `KernelOrCompile`（`backends/compile/choice.py`）：

- **候选。** 只调优在该架构上支持该算子且优先级最高的后端（sm70 / sm75 上的 TileLang，sm80+ 和 XPU 上的 Triton）。候选为该后端的内核和 `torch.compile(eager reference)`。
- **回退。** 后端构建或运行失败时记录一次日志，注册表回退到优先级中的下一个后端，然后以同样方式计时；第一个可用后端之后的后端不会构建或计时。无法在某设备上运行的内核（每个设备在 `no_grad` 下检查一次）会在该设备上绑定 eager 参考实现。
- **绑定。** 每次调用按问题形状绑定该卡已存储的两个候选中的优胜者，否则绑定内核。调用内部不进行计时，因此前向与其梯度检查点重计算始终使用相同实现，`no_grad` / `inference_mode` 调用也绝不会运行反向计算。
- **测量。** `TUNE="table"` 时，没有已存储优胜者的问题会排队。`retune_pending()` 通过共享调优器（`select(..., autograd=True)`）测量排队的问题（合成输入上的前向 + 反向）。训练中会在两个位置运行：
  - 预热重放（`kohakumoss_kernels.tuning.replay`）在第 0 步之前测量每个 token 桶；
  - `RetuneKernels`（`kohakumoss.training.callbacks.kernels`）在前 `RETUNE_STEPS` 步（默认 3）中的每步之后运行，处理在这些步骤中首次遇到的问题。最后一步之后，`window.seal()` 停止内核与编译路径比较的排队：不再将新问题加入队列，仍在排队的问题继续使用内核。首个采样网格的窗口仍会对其自身形状的缺失键计时。
- **不计时的情况。** `retune_pending()` 在推理模式下、启用梯度检查点的前向或反向内部，或 `TUNE="off"` 时不计时；这类问题继续排队，直到允许计时的重新调优，或者在内核与编译路径比较的排队被封闭后继续使用内核。

调优窗口见 [tuning.md](tuning.md#tuning-windows)。

<a id="the-compiled-path"></a>
### 编译路径

注册的编译路径为 `torch.compile(eager, dynamic=True)`：一个计算图服务于所有 token 数，因此长度变化的打包批次从不触发重新编译，梯度检查点重计算也始终遇到其前向运行过的图。`dynamic=None` 会以静态方式追踪第一个长度，并在第二个长度时重新编译，这就会使较早微批次尚未执行的重计算遇到不同的图（`test_kernel_or_compile.py` 检查计算图数量）。

每种调用模式都有自己的编译后可调用对象（`CompiledOp`，`backends/compile/ops.py`），由 eager 参考实现代码对象的新副本构建，因此每种模式都有自己的 Dynamo 缓存和重新编译预算。调用模式包括 Dynamo 守卫的全局状态（梯度模式、算子内线程数、autocast dtype），以及每个参数的 dtype / requires_grad / 秩、None 或 Python 标量。

- 为什么按模式区分：所有模式共用一个缓存时，每种新模式都会触发重新编译。
  - 使用 LoRA 时，第 0 块的输入被冻结，因此各块的 requires_grad 不同。
  - 梯度检查点重计算在 autograd 线程上运行，其算子内线程数与主线程不同。
  - 超过 `recompile_limit`（8）后，Dynamo 会以 eager 方式运行代码对象。此前以编译方式运行的梯度检查点前向随后遇到 eager 重计算，torch.utils.checkpoint 会抛出 "a different number of tensors was saved"。
- 每种模式通过计数后端编译，超过 `GRAPH_LIMIT`（8）个图就会抛出 `GraphLimitError`。Dynamo 自身的限制被提升到至少 64 / 4096，因此计数后端会先抛出异常。
- `test_compiled_checkpoint.py` 在默认限制下，将重计算状态的调用与单缓存变体进行比较。

块算子基准测试（`scripts/bench/kernel/`）将这条路径报告为 `compile_dyn`，与静态形状的 `torch.compile(eager, dynamic=False)`（`compile`）并列，后者是每种形状的最佳情况；`selected` 列为内核和 `compile_dyn` 中较快的一项。

<a id="real-model-structural-tests"></a>
## 真实模型结构测试

真实权重测试（`tests/integration/`）比较同一数学计算的两次运行。在 42 块 MOSS-Image 骨干网络上（随机 latent 和文本，数百个 token），一次前向的两种有效实现（另一种问题形状，因此采用另一种 GEMM 分块或另一个绑定的内核 / 编译优胜者）会产生以下相对 L2 误差（RTX 5090）：

| 比较 | bf16 | fp16 |
| --- | --- | --- |
| 打包批次与各样本单独运行 | 0.052 | 0.0068 |
| 打包批次与相同批次加上一个零填充样本 | 0.050 | 0.0064 |
| 以 2^-4 进行门控折叠与未折叠 | 0（新进程），0.040（绑定了其他优胜者） | 0.0065 |
| 交换两个样本的文本长度（错误布局） | 0.26 | 0.26 |
| 负向跳层与运行每个块 | 0.43 | 0.43 |

各测试的界限：

| 测试 | dtype | 界限 |
| --- | --- | --- |
| `test_model_real.py` | fp16 | 2e-2：其舍入噪声的 3x，比错误布局低 13x |
| `test_fold_real.py` | bf16 | 折叠与未折叠之差在 0.12 以内（另一种绑定的 0.040 的 3x，低于错误布局的 0.26）；展开将未折叠输出恢复到 1e-6 |
| `test_sampling_real.py` | bf16 | 打包 CFG 与两遍 CFG 的差异在其实测噪声底的 3x 以内 |

- `test_fold_real.py` 以 bf16 运行，因为 2 的幂折叠在该格式下能精确缩放每个权重。在 fp16 中，折叠不可逆：低于最小正规数 16x 的权重会作为非正规数丢失位。
- `test_sampling_real.py` 测量自身的噪声底：两遍 CFG 每次运行一个样本与每次运行两个样本比较（bf16 下一步之后每样本为 0.040-0.048；四步之后为 0.14-0.17，此时轨迹放大了差异）。打包 CFG 相对于两遍 CFG 测得 0.039-0.059；若向打包 CFG 的无条件半区输入正向文本，latent 会偏移 0.70-0.75。噪声底至少为 bf16 舍入尺度（2^-7）。
- `test_resume_real.py`：训练反向计算在多次运行间并非按位可复现（两次相同运行的第 1 步：损失相同，梯度范数为 0.022149 与 0.022184），AdamW 会放大接近零的适配器张量上的差异。进行 4 步 LoRA 运行后，各类检查点张量的相对差异中位数如下：

  | 类型 | 第二次完整连续运行 | 从第 2 步恢复 | 恢复时不恢复步生成器 |
  | --- | --- | --- | --- |
  | lora_up | 0.145 | 0.054 | 0.46 |
  | lora_down | 0.013 | 0.0047 | 0.033 |
  | exp_avg | 0.44 | 0.43 | 1.08 |
  | exp_avg_sq | 0.32 | 0.26 | 0.87 |

  测试将完整连续运行执行两次，并要求恢复运行的每一类差异均在第二次完整连续运行差异的 1.5x 以内（原本精确的地方仍须精确）；普通值、计数器和整数张量必须相等，恢复后的第一步损失必须按位一致。
- `test_train_real.py` 比较不同内存配置档的第 1 步损失和梯度范数，每个配置档都设置 `VAE_ENCODE={"compile": "off"}`。LoRA 初始化时（up 因子为零），第 1 步梯度范数对批次非常敏感：编译后的 VAE 编码（`compile="auto"` 仅编译常驻 VAE）与 eager 编码产生的 latent 存在 bf16 舍入差异，随后不同配置档的梯度范数会相差 17-44%（0.0318 与 0.0178）。每个配置档都使用 eager 编码时，`balanced` 和 `minimal` 的差异在 0.1% 以内（0.017770 与 0.017790）。
- `test_adapters_real.py` 将一个适配层的误差统计与 fp64 比较（`tests/_util/error_stats.py`），其舍入尺度下限（bf16 eps 2^-7，10x）会让丢弃百分之几的增量也能通过。在检查之前，会向该层适配器注入标准差 0.1 的噪声，使增量约与基座权重同量级，因此丢弃增量会让输出远超这些下限，导致检查失败。
