# 变长注意力

将各架构的打包变长注意力与 PyTorch 对比，分别测量前向 + 反向和仅前向，再衡量其相对 fp64 的精度。对于前向 + 反向，绑定的入口在每张已测显卡的每个用例上都胜过 SDPA；对于较长的单段形状，如果构建版本提供 torch 自身的 `varlen_attn`，则绑定该实现（[单段性能上限](#the-single-segment-ceiling)）。

<a id="columns"></a>
## 列说明

| 列 | 含义 |
| --- | --- |
| ours | 该架构注册的 `attention_varlen`（基准测试标签为 `kohakumoss_<backend>_chosen`）：按问题键，对后端内核（sm70 / sm75 使用 TileLang，sm80+ 使用 Triton）与 torch 的 `varlen_attn`（若 torch 构建版本提供；否则使用逐段 SDPA 循环）进行前向 + 反向计时，并绑定更快者 |
| kernels | 仅后端自身的内核（`kohakumoss_<backend>_kernels`） |
| SDPA | PyTorch 的逐段 `scaled_dot_product_attention`（sm80+ Linux 上使用 flash，sm70 / sm75 和 Windows 上使用 memory-efficient） |
| varlen_attn | torch 基于 FA2 的变长算子（仅限 Linux sm80+ 构建版本） |

在精度统计与 PyTorch 相当的实现中（见[精度](#precision)），入口按形状绑定最快者。每一行基准测试都记录选定入口绑定了什么（`bound`），以及 o、dq、dk、dv 相对 fp64 的误差统计（`stats`）。

<a id="method"></a>
## 方法

- 基准测试：`scripts/bench/kernel/attention.py`，24 个头 x 128。
- 用例：打包的段，每段由一张 1 MP / 2 MP / 512 px MOSS 图像的图像 token 加上其描述文本组成；文本精炼器用例仅包含描述文本。
- 时间：每次调用的设备时间，取 10 次中的最佳值（CUDA events）。前向 + 反向取交错轮次的中位数（`--rounds`；每轮依次为每个实现计时，取该轮各次调用中的最佳值）。
- 内存：相对用例开始时已分配量的增量峰值。
- 误差：对其中 2 个头，相对 fp64 运行结果计算。
- 填充版 SDPA 基线在计时区域内在主机上读取段边界，与该 PyTorch 路径实际使用时的行为一致。

<a id="the-single-segment-ceiling"></a>
## 单段性能上限

只有一个长段时，逐段 SDPA 就是一次 FA2 调用，而 FA2 的运行速率达到了该显卡实测的 16 位 MMA 速率（fp32 累加；`hardware.device.measure_rates`）：

| 显卡 | MMA 探测值 | FA2 前向 (2 MP x1) | FA2 反向 (2 MP x1) | 我们的前向 | 我们的融合反向 |
| --- | --- | --- | --- | --- | --- |
| RTX 3090 | 68 TFLOP/s | 75 TFLOP/s | 74 TFLOP/s | 76 TFLOP/s | 63 TFLOP/s |
| RTX 5090 | 233 TFLOP/s | 228 TFLOP/s | 232 TFLOP/s | 235 TFLOP/s | 200 TFLOP/s |

（前向 = 2 次 GEMM，反向 = 5 次 GEMM，每次为 `2 N^2 D H` 次浮点运算。）对于这些形状，任何使用 fp32 累加的内核都已没有提升空间，因此入口在这些情况下绑定 torch 的 `varlen_attn`，在 2 MP x1 上比 SDPA 的前向 + 反向快 0.6 - 1.6 %（加速比表中的 1.01x / 1.02x；它省去了 SDPA 的布局转置）。我们的前向达到相同速率；我们的反向在两张显卡上都保持在 FA2 的 85 - 86 %；分块研究见 [kernel-dev.md](../internals/kernel-dev.md#measured-design-per-arch)。对于每种打包或短段形状，我们的内核（或入口绑定的 `varlen_attn`）都比 SDPA 的前向 + 反向快 1.08 - 4.39x（见加速比表），因为一次启动即可覆盖所有段。

<a id="precision"></a>
## 精度

两者的结果都与 fp64 比较（余弦相似度；|out - ref|；在非零 ref 上计算的 |out - ref| / |ref|），使用 RTX 5090，ours = 已注册入口，SDPA = PyTorch 的 flash。我们的实现与 PyTorch 的每次注意力矩阵乘法都采用 16 位操作数和 fp32 累加（[kernel-dev.md](../internals/kernel-dev.md#matmul-precision-and-error-statistics)）。最小值均为零或低于 1e-8，故省略。

fp16，1 MP x2：dq、dk、dv 的所有统计量与 SDPA 的差异都在 1 % 以内（余弦相似度 1.0000000）；o 的绝对误差均值为 5.46e-6，对比 5.28e-6，相对误差均值为 1.96e-3，对比 2.19e-3，相对误差最大值为 397，对比 790。

比 SDPA 差的部分及其原因：两种 dtype 下，o 的均值 / 中位数误差都比 flash 高 3 - 4 %（bf16 的绝对误差均值为 4.37e-5，对比 4.22e-5）。两个内核从不同形式的指数将 P 舍入到 16 位（我们的实现使用原始行最大值计算 `exp2((s - m) c)`，flash 使用 `exp2(s c - m c)`）；余弦相似度在 7 位数字上相同。dq / dk / dv 的相对误差最大值在任一方向上的差异可达 2x（各由一个元素造成，其参考值接近零）。

聚簇的查询和键（logits ~1e5），bf16，测试的第一次抽样：dQ 余弦相似度为 0.988（我们的实现），对比 0.974（SDPA），绝对误差均值为 7.5e-3，对比 1.06e-2；dK 余弦相似度为 0.99996，对比 0.99988；dV 为 0.999998，对比 0.99999。此处相对统计量受接近 1e-190 的 fp64 参考值主导（见 kernel-dev.md），不作比较。

XPU 运行相同的内核。在每种设备上，测试的 PyTorch 基线都是以 16 位 dtype、在设备选择的 SDPA 后端上运行的普通逐段 SDPA（`pytorch_sdpa`，见 kernel-dev.md），以 fp64 作为参考；上面的 SDPA 行是在 RTX 5090 上运行的 flash SDPA。
