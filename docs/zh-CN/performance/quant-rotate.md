# 旋转 int8 linear（ConvRot）

由 `scripts/bench/kernel/rotate.py` 测量（普通 int8 linear 使用 `quant.py`），
每张显卡在 `runs/kernel/` 下有一个 JSON。设计见
[quant-kernels.md](../internals/quant-kernels.md#rotated-int8-linear)。

列说明：

* **rotation**：仅在 x [M, K] 上使用 `group_hadamard`（g = 256），在最快的后端上；
* **int8 fwd** / **rotated fwd**：注册的 `quant_linear` 和 `quant_linear_rotated`
  前向，按调优器实际选定的结果；
* **fwd x** / **fwd+bwd x**：旋转相对普通版本的倍数（前向，然后是前向 + 输入
  梯度）；
* **separate / best fused**：调优器自身测得的旋转前向和 dgrad 候选的设备时间。

所有时间均为设备 ms（profiler 内核时间）；fp16 各行与 bf16 各行的差异在几个百分点
以内。

| 显卡 | 状态 |
| --- | --- |
| RTX 3090 (sm86) | 见下文实测 |
| RTX 4090 (sm89) | 待测：池中没有 sm89 显卡 |
| V100 (sm70) | 待测：主机不可达 |

* 旋转的运行速率约为 830 GB/s（x 的读 + 写），因此其占比是 x 的字节数除以 GEMM
  时间：在小型 `o` GEMM 和 K = 8192 的 `down` 输入上最大。
* 融合前向在 CUDA 核心上为每个输出图块旋转一次 x 图块（共 N / BN 次），耗时约为
  单独一轮的 2x；融合 dgrad（每个输出图块旋转一次，但输出图块固定为 256 宽）为
  1.2-1.3x。调优器在这张显卡上对所有形状都选择 `separate`。
* 在这张显卡上，普通 int8 linear 与编译后的 dequantize + matmul 相当。调优器按形状
  选择 Triton 图块或编译路径。
  * 前向：4096 个 token 时大多由图块胜出，16384 个 token 时由编译路径胜出。
  * Dgrad：编译路径在所有形状上都胜出。
  * 除一行（bf16 3072 x 3072、4096 个 token）之外，所选路径与更快的 PyTorch 路径的
    差距都在 3% 以内。
