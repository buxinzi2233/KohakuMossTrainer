# 合成块上的卸载引擎（V100、RTX 4090）

在 V100 32 GB 和 RTX 4090 上，测量每个卸载选项的步骤耗时、峰值内存和复制量，以及每种组合距离其硬件下界有多近。这些块是 MOSS 规模的合成块：它们测量引擎的复制与计算成本，而不是模型输出。RTX 5090 上真实模型的数据见 [offload.md](../internals/offload.md#real-model-benches-rtx-5090)；该文也描述了这些引擎本身。

表格阅读说明：

| 术语 | 含义 |
| --- | --- |
| ms / 步 | 一次优化器步骤 |
| 峰值 GiB（已分配） | torch 分配器的已分配字节峰值（存活张量，不是预留量或设备使用量） |
| H2D / D2H GB | 每步主机到设备 / 设备到主机的字节数 |
| 重叠比 | 步骤耗时 / `max(copy bound, compute)`；1.00 = 步骤仅消耗其下界所需的时间 |
| - | 该用例中没有此类复制 |

基准测试：`scripts/bench/offload/{stream,knobs,limits}.py`，每个用例一个进程。

## 单独测量每个显存选项

MOSS 规模的合成块（仅测复制 / 计算成本，无模型输出），工作树 a3cfbe0。
`scripts/bench/offload/knobs.py`，每个用例一个进程，在 V100 上以 fp16 运行 8 个块（0.75 B 参数），在 RTX 4090（Windows）上以 bf16 运行 4 个块，4400 个 token，GRAD_ACC 2：

| 选项 | V100 32 GB fp16：ms / 步 | 峰值 GiB（已分配） | 每步 H2D / D2H GB | RTX 4090 Windows（4 个块，bf16）：ms / 步 | 峰值 GiB（已分配） |
| --- | --- | --- | --- | --- | --- |
| 全量微调，设备端 AdamW | 832 | 6.92 | 0 / 0 | 301 | 4.01 |
| 全量微调，CPUAdamW（梯度在设备端） | 1607 | 4.11 | 0 / 0 | 421 | 2.60 |
| 全量微调，梯度卸载 + CPUAdamW | 1808 | 2.71 | 0 / 3.02 | 455 | 1.90 |
| 冻结块，无梯度检查点 | 490 | 7.59 | - | 187 | 3.94 |
| 冻结块，块级梯度检查点 | 708 | 2.56 | - | 317 | 1.76 |
| 冻结块，子块级梯度检查点 | 703 | 2.49 | - | 233 | 1.58 |
| 冻结块，选择性梯度检查点 | 542 | 4.04 | - | 204 | 2.39 |
| 冻结块，梯度检查点 partial:0.5 | 601 | 4.75 | - | 211 | 2.52 |

<a id="hardware-limit-check"></a>
## 硬件极限检查

MOSS 规模的合成块（仅测复制 / 计算成本，无模型输出），工作树 a3cfbe0。
`scripts/bench/offload/limits.py`，每个用例一个进程，4400 个 token，块级梯度检查点，`stream_resident=2`。复制下界取以下三者的最大值：H2D 字节数 / 页锁定 H2D 带宽、D2H 字节数 / 页锁定 D2H 带宽，以及总字节数 / 实测并发（双向）带宽；计算时间取相同 GRAD_ACC 下的常驻步骤时间。

| 用例 | V100 32 GB，8 个块，fp16：ms | 重叠比 | RTX 4090 Windows，4 个块，bf16：ms | 重叠比 |
| --- | --- | --- | --- | --- |
| 全量微调常驻，GPU AdamW | 459 | 1.00 | 228 | 1.00 |
| 同上，GRAD_ACC 4 | 1756 | 1.00 | 564 | 1.00 |
| 梯度卸载，在反向传播中执行 GPU AdamW，GRAD_ACC 4 | 2116 | 1.20 | 584 | 1.03 |
| 优化器状态流式传输（`stream`），融合步骤 | 2474 | 1.34 | 416 | 1.18 |
| CPUAdamW | 1220 | 2.66 | 260 | 1.14 |
| `swap`，GPU AdamW，状态常驻 | 666 | 1.45 | 170 | 0.74 |
| `swap`，GPU AdamW，状态流式传输 | 3068 | 1.35 | 457 | 1.07 |
| 同上，GRAD_ACC 4 | 5190 | 1.39 | 925 | 1.40 |
| `swap`，CPUAdamW | 1558 | 3.40 | 285 | 1.25 |
| 适配器（冻结块）常驻 | 354 | 1.00 | 120 | 1.00 |
| 适配器，激活卸载 | 355 | 1.00 | 120 | 1.00 |
| 适配器，`ring` | 439 | 1.24 | 118 | 0.98 |
| 适配器，`ring` + 激活卸载 | 452 | 1.22 | 126 | 1.06 |
| 适配器，`ring` + 梯度卸载 | 501 | 1.42 | 116 | 0.97 |
| 适配器，`ring` + 激活卸载 + 梯度卸载 | 512 | 1.38 | 125 | 1.05 |
| 适配器，`ring`，int8 基座 | 389 | 1.10 | 131 | 1.10 |

带宽：V100 页锁定 H2D 6.70 GB/s，D2H 6.61 GB/s，双向合计 9.80 GB/s；RTX 4090（WDDM）25.1 / 26.3 GB/s，双向合计 25.7 GB/s（无双工增益）。
MMA 峰值为 90 TFLOP/s（V100 fp16）、175 TFLOP/s（4090 bf16）。

- **流式传输的优化器状态**每步每个参数在每个方向各移动 12 字节。V100 上重叠比为 1.34-1.39 的行受复制限制：性能分析显示，更新内核完全被隐藏，复制引擎在整个步骤中始终忙碌。
- **CPUAdamW** 受主机更新限制，而不是 PCIe 或 GPU 限制。
- **状态常驻的 `swap` 和单独的 `ring`** 在各阶段内受复制限制：采用 2 槽环形缓冲区的前向传播需要等待每个块的 H2D，因此按整个步骤求和会低估下界。
- **V100 上的 `ring` + 梯度卸载**比单独的 `ring` 更慢，尽管传回主机的梯度只有适配器规模：D2H 梯度复制进行期间，权重环形缓冲区的 H2D 速度约降低 18%。
- **4090 上状态常驻的 `swap` 为 0.74：** 常驻参考实现在反向传播完成后，对完整大小的梯度执行 AdamW，而 `swap` 在反向传播内部逐块执行优化器步骤。因此，常驻参考实现并不是反向传播内部执行优化器步骤的下界。
